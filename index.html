SOAR · AWS · Fully automated

IAM user automated containment

When GuardDuty flags compromised IAM credentials, the user is locked out automatically with no human in the loop.

GuardDuty→EventBridge→SSM Automation→User contained
  • Containment disables access keys, removes console access, attaches a deny-all policy and tags the user.
  • Backs up the original configuration so the change can be reversed after investigation.
  • Least-privilege roles with protected emergency accounts; tested end to end in a lab with every step succeeding.

SOAR · AWS · Human approval

EC2 compromise containment

When GuardDuty detects a compromised EC2 instance, the security team is emailed and an engineer approves containment before it runs.

GuardDuty→EventBridge→SNS email→Engineer approves→SSM document→Instance isolated
  • Alerts reach the security team by email the moment a compromised instance is detected.
  • An engineer approves before the privileged SSM document runs, keeping a human decision on production servers.
  • The document takes backups for forensics, then isolates the instance by swapping its security groups.
